# SZB Salary Pack · Пакет продавца зарплатного проекта Сбера

**Версия инфраструктуры:** 1.6E (26.11.2026). **Содержательная версия:** 1.6D, без изменений продуктовых условий и визуального оформления в 1.6E.

**Действующий адрес:** https://alekseik83.github.io/SZB_salary_pack/#home

Неофициальный справочный материал для сотрудников банка. Для передачи клиентам используются только утверждённые формы предложений и презентаций. Цены, льготы и сроки зависят от действующих документов банка; дата обновления отдельного предложения не означает, что оно проверено сегодня.

## Где находится действующая версия

GitHub Pages предполагается настроенным на **ветку `main`, папку `/(root)`** — сверяйте это в **Settings → Pages**. Именно в корне `main` находятся публикуемые файлы:

| Путь | Для чего нужен |
| --- | --- |
| `index.html` | Основной лендинг: 26 разделов, 25 мини-баннеров, подбор ТОП-фич, калькулятор, поиск |
| `paket-prodavca-zp.pdf` | Утверждаемый отдельно четырёхстраничный пакет продавца |
| `fonts/`, `img/`, `qr-privilegii.png`, `qr-privilegii.svg` | Ресурсы сайта и QR |
| `.github/workflows/validate-szb.yml` | Регрессионные тесты исходной версии на push/PR |
| `.github/workflows/verify-pages.yml` | Независимая сверка опубликованного сайта по SHA-256 — вручную и ежедневно |
| `suflyor/` | Самостоятельный инструмент, не входящий в приёмку лендинга 1.6E |

**Папка `release/` — историческая копия, а не источник текущего лендинга.** В проверенном архиве её `index.html` и PDF побайтово совпадают с корнем, а четыре старых Python-скрипта не используются действующим workflow. Её можно удалить после подтверждения `Settings → Pages: main / (root)` и отсутствия нужных кому-либо ссылок на `/release/`. Не удаляйте папку в том же коммите, что обновляет workflow: сначала убедитесь в успешном запуске 1.6E.

## Что проверяет релиз 1.6E

**E01 — реальная публикация.** Workflow `SZB Salary Pack published version` скачивает с публичного HTTPS-адреса `index.html`, PDF, используемые изображения и шрифты и сравнивает SHA-256 с файлами корня `main`. Запускается вручную (`Actions → SZB Salary Pack published version → Run workflow`) или раз в день. **Не публикует сайт, не модифицирует репозиторий.** Если Pages ещё не закончил обновление или CDN отдаёт старую копию, проверка честно завершится с ошибкой: повторите её после публикации. Это отдельная проверка, не связанная с зелёным статусом CI.

**E02 — сроки.** Браузерный тест проверяет акцию с датой `2026-11-30` в трёх состояниях: 30 ноября — действующая; 1 декабря — помечена завершённой; 9 декабря — скрыта из списка главной и помечена как завершённая в разделе. Проверка моделирует часы Chromium, не использует запрещённый параметр `?today=`. Никакие условия акции автоматически не редактируются.

**E03 — понятная структура.** Актуализирован этот README; для выпуска не нужны скрипты в корне репозитория и новые папки с дублями.

**E04 — регрессия.** На ширинах 320/390/768/1440 px проверяются навигация по ключевым разделам, подбор, калькулятор, работа поиска, пустая выдача, повторное открытие, клавиатура и горизонтальная прокрутка. Доступность статических файлов по HTTPS контролирует E01. Тестирование Safari и реальных устройств не входит в автоматическую приёмку.

## Точный порядок прямой загрузки в main (без ветки релиза)

**Меняются только три файла.** Откройте репозиторий и убедитесь, что выбрана ветка **`main`**. ZIP целиком в GitHub загружать нельзя.

1. **Корень репозитория** — замените `README.md` файлом новой редакции.
2. **Папка `.github/workflows/`** — замените `validate-szb.yml` файлом новой редакции.
3. **Та же папка `.github/workflows/`** — добавьте новый `verify-pages.yml`.
4. Проверьте GitHub → **Actions**: workflow **SZB Salary Pack integrity** должен завершиться успешно. Код `index.html` и PDF не нужно загружать заново.
5. После завершения публикации сайта запустите отдельно **SZB Salary Pack published version** → **Run workflow** (ветка `main`). В успешном журнале должна появиться строка `PUBLISHED_SITE_MATCHES_MAIN`.

Ежедневная проверка опубликованного сайта может иногда показать временное расхождение из-за публикации или кеша. Это **не значит**, что основной лендинг сломался: выясните причину, прежде чем что-либо заменять.

**Очистку папки `release/` проводить только отдельным коммитом после успешного прогона 1.6E.** Она не участвует в основных тестах; удаление сломает только старые ссылки, содержащие `/release/`, если такие используются. Перед удалением проверить **Settings → Pages → Build and deployment**: публикация должна идти из `main / (root)` или из другого специально настроенного источника, который точно не зависит от `release/`.

Если проверка живого сайта сообщает `Published content differs`, сначала проверьте источник Pages, статус публикации и CDN-кеш. Не заменяйте целиком `index.html` или PDF без установленной причины.

## Разделы и ссылки

Всего **26 отдельных `section.view`**: 11 для компании, 10 для сотрудников и 5 инструментальных разделов.

- Компании: `biz-money`, `biz-requisites`, `biz-sberbusiness`, `biz-cards`, `biz-preferences`, `biz-citycard`, `biz-gig`, `biz-team`, `biz-hr`, `biz-launch`, `biz-anybank`.
- Сотрудникам: `emp-card`, `emp-security`, `emp-cashback`, `emp-credit`, `emp-savings`, `emp-mobile`, `emp-partners`, `emp-promo`, `emp-premium`, `emp-switch`.
- Инструменты и справка: `pick`, `calc`, `objections`, `sources`, `updates`.

Домашние режимы `#home`, `#companies`, `#employees` и `#bank-site` — не отдельные `section.view`. Пример глубокой ссылки: https://alekseik83.github.io/SZB_salary_pack/#emp-mobile.

Чтобы дополнить ленту новостей без изменения функциональности, измените массив `UPDATES` в корневом `index.html` и пройдите обычную приёмку. Продуктовые цифры и условия перед изменением требуют согласования.

## Доступ и конфиденциальность

Репозиторий и GitHub Pages публичные. `noindex` и `robots.txt` не ограничивают доступ к HTML/PDF и не гарантируют отсутствия в выдаче поисковиков. Не размещайте на сайте закрытые банковские документы, персональные данные, API-ключи или записи клиентов. Инструмент `suflyor/` требует отдельной оценки конфиденциальности: проверка 1.6E его не охватывает.
